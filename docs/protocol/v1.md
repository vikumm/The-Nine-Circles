# Protocol v1

Status: VS-006 game ticket gate.

## Package

The stable Protobuf package is `divinity.protocol.v1`.

C# generation uses namespace `Divinity.Contracts.V1` through `Grpc.Tools` and `Google.Protobuf`.

## Envelope Rules

Client messages are wrapped in `ClientEnvelope`:

- `protocol_version`;
- `sequence`;
- `client_tick`;
- exactly one client intent payload.

Server messages are wrapped in `ServerEnvelope`:

- `protocol_version`;
- `server_tick`;
- `ack_sequence`;
- exactly one server payload.

The conceptual envelope size limit is 64 KiB. Gateway code must reject larger payloads before expensive parsing.

## Server Authority

Client payloads are intents only. The v1 client contract does not allow clients to send:

- final damage;
- XP grants;
- currency grants;
- loot rarity;
- item instance ownership or attributes;
- completed cooldowns;
- collision resolution;
- final authoritative position;
- death decisions.

## VS-003 Gateway Smoke

`POST /protocol/v1/client-hello` accepts `application/x-protobuf` bytes containing a `ClientEnvelope` with `ClientHello`.

When called through the compatibility handler without a ticket store, this endpoint remains a protocol smoke check only:

- it validates size, Protobuf parsing, `protocol_version` and payload type;
- it returns a controlled `ServerEnvelope` response;
- it does not authenticate, consume tickets, open WSS, create sessions or route gameplay.

## VS-006 Game Ticket

Platform API issues a short-lived game ticket through `POST /launcher/game-ticket` after launcher authentication has produced an account identity.

The issue request binds the ticket to:

- account id resolved server-side;
- `buildId`;
- `protocolVersion`;
- `nonce`.

The response contains the bearer `gameTicket`, `expiresAtUtc` and `ttlSeconds`. The ticket TTL is 30 seconds.

Game Gateway consumes the ticket from `ClientHello.game_ticket` when it receives `POST /protocol/v1/client-hello`.

Consumption rules:

- the ticket is single-use;
- consume is atomic in the configured shared store;
- malformed, missing, invalid, expired, reused, build mismatch, protocol mismatch and nonce mismatch are rejected with controlled `ServerError` responses;
- accepted tickets return `CLIENT_HELLO_ACCEPTED_NO_SESSION` because authenticated WSS session establishment remains out of scope until VS-007.

Ticket secrets must not be placed in URLs, logs, traces or CLI arguments.

Authenticated WSS handshake is reserved for VS-007.

## Compatibility

Future compatible changes may add new field numbers without reusing or changing existing field meaning. Incompatible changes require a new package version such as `divinity.protocol.v2`.

Fields already assigned in v1 must not be renumbered. Client-authored payloads must remain intent-only.
